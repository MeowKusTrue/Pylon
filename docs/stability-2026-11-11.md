# Стабильность Pylon — 11 ноября 2026

Исправления после 2.1.3, включённые в релиз 2.1.4. Собственный движок остаётся необязательной настройкой, по умолчанию выключенной.

Продолжение работ и актуальная проверка: [followup-2026-11-11.md](followup-2026-11-11.md). Ниже сохранён отчёт первого этапа с 79 проверками.

## Исходные пять задач

1. **Офлайн-загрузки.** В имя входит 128-битная часть SHA-256 адреса источника. Названия после очистки могут совпадать, идентификаторы разных источников — различаются. Проценты экранируются для шаблона yt-dlp; включён запрет перезаписи. Загрузки сериализованы между плейлистами, чтобы два процесса не писали один `.part`. Старые файлы и ссылки библиотеки не переименовывались.
2. **Переключение движка.** FirstFrame, Ended, субтитры и отказ проверяют активный экземпляр. Поколение проверяется повторно после доставки событий в UI; отложенная работа с изображением проверяет запрос воспроизведения. Отменённое открытие не начинается после ожидания старого закрытия. Старый экземпляр получает остановку сразу; освобождение ресурсов остаётся вне UI. Добавлена проверка с заблокированным открытием: старые события не изменяют новый трек, оба отменённых экземпляра освобождаются без GPU и звука.
3. **Склейка.** В ffmpeg передаётся выбранный ConvertPreset, расширение соответствует пресету. При ошибке копирования объясняется необходимость совместимых кодеков и параметров. Разные кодеки исходных частей автоматически не нормализуются: сначала их нужно конвертировать в один формат. MP3 и FLAC проверены настоящим ffmpeg.
4. **Звук и сон.** Если выбранный уровень с gain превышает возможности собственного выхода, используется libVLC с сохранением позиции и состояния паузы. Предел собственного усиления и кривая громкости не увеличивались. Последние десять секунд сна регулируют оба выхода через ApplyVolume; изменение громкости во время затухания учитывает таймер, отмена восстанавливает уровень. Исходный разовый акустический скачок не воспроизведён.
5. **Длинные записи.** Время использует общее число часов; `25:02:03.5` сохраняет значение при форматировании и обратном чтении.

## Остальные согласованные улучшения

- **Профиль.** Ошибки чтения и повреждённый JSON не превращаются в пустые настройки с последующей перезаписью. До создания главного окна предлагается выбрать другую папку или завершить запуск; исходные файлы сохраняются. Проверяются обязательные коллекции библиотеки и возможность записи в каталог. Канал единственного экземпляра учитывает выбранный профиль. Недоступная папка переводов не блокирует запуск.
- **Сохранность конвертации.** ffmpeg пишет временный файл рядом с результатом. После успешного завершения выполняется переименование без перезаписи. Ошибка, отмена и совпадение выходного имени не удаляют существующий файл. Проверены реальное завершение, конфликт и заранее отменённый запуск.
- **Отчёт о проблеме.** Существующий отчёт дополнен режимом интерфейса, дисплеями, активным движком и звуком. Предпросмотр содержит именно текст из будущего ZIP. Пути, HTTP-адреса с параметрами и типичные секреты очищаются до предпросмотра. Человек выбирает место сохранения; ничего не отправляется автоматически.
- **Открытие медиа.** Видимый статус, кнопка отмены и Esc. Запрос имеет номер: отменённое извлечение ссылки или чтение метаданных не запускает файл позже. Остановка открытия выполняется вне UI, следующий запуск ждёт её завершения. Уже начатый поиск ссылки может завершить сетевую работу в фоне; его результат после отмены не воспроизводится.
- **Отдельные дорожки.** После начала воспроизведения предупреждение показывается при явной ошибке декодера и отсутствии декодированных кадров соответствующей включённой дорожки. Сообщения доступны в последней ошибке; окно не утверждает, что весь файл не открывается. Это не обнаружение всех возможных видов тишины или повреждения.
- **Тексты и распознавание.** Неудача сервиса отличается от отсутствия совпадения. Распознавание отдельно объясняет отсутствие локального файла, инструмента, пригодного аудио и короткий фрагмент. В панели текстов есть повтор и поиск под другим названием. Результаты параллельного поиска не используют общий глобальный статус.
- **Возможности движка.** Необычные настройки HDR/апскейла и HDR-видео PQ/HLG передаются libVLC. Отказ собственного движка показывается пользователю с причиной. Это не обещание поддержки всех режимов HDR на любой видеокарте: GPU, драйвер и дисплей по-прежнему отражаются в диагностике.

## Проверка

- Release Checks: 79 проверок с реальным ffmpeg; данные только в изолированном PYLON_DATA, запуски последовательно.
- Debug publish; снимок русского предпросмотра отчёта: `D:\Temp\pylon-next-ui\report.png`.
- Проверка доставки событий в настоящее WPF-окно во время ожидания остановки: FirstFrame, Ended и Failed старого экземпляра не меняют новый запрос; `own-event-race passed=True`, `D:\Temp\pylon-next-ui\race.state.txt`. GPU-устройство не создавалось.
- Локальный сервер с задержкой ответа: до отмены Opening, кнопка видима; через 12 секунд после отмены Stopped, воспроизведение не возобновилось. Состояния: `D:\Temp\pylon-next-ui\cancel.state.txt`. Сервер работал внутри тестового процесса только на loopback, с ограничением времени.
- Журнал Checks: `D:\Temp\pylon-next-checks.log`.

Не проверены акустические уровни через физический выход, чужая урезанная Windows и исходные неназванные треки, все пресеты склейки на всех сочетаниях исходников, реальные службы распознавания на пользовательских примерах. Тяжёлые GPU-тесты не запускались. Конкретная видеокарта не объявляется поддерживаемой только по названию.
