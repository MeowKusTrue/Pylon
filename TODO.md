## Перемотка и переходы (2026-10-20) — сделано в 2.0.1, кроме отмеченного

- Сделано: hurry-up снова включён (H.264 60 fps после перемоток 60 вместо 31); перемотка на ключевой кадр в TS / M2TS (FFmpeg-демуксер, прицел на 30 мс раньше кадра: его поиск приземляется сразу после найденного пакета) и MPEG-PS (по байтам, демуксер libVLC) — `Keyframes.cs`; умный переход (по тишине из кэша волны), без перехода внутри альбома, мягкая пауза (громкостью плеера: усиление доходит до вывода на ~0,5 с позже).
- FLV отдельной доработки не требует (ломался из-за hurry-up).
- Не делал: превью вместо замершей картинки (кадры превью 256×144 и только через каждые 0,5 % файла — показали бы чужой кадр; после исправлений заминка 0,16–0,2 с), быстрые прыжки при перетаскивании (в libVLC 3 fast-seek только общий переключатель движка).
- **Найдено, ждёт решения пользователя:** вывод DirectSound в libVLC 3 обрезает конец КАЖДОГО файла на 0,5–1,2 с (нет drain: конец файла приходит, пока звук ещё в буфере, и буфер выбрасывается). waveout играет до конца (замер маркерами 300 Гц), чистота та же (65,8 дБ), 0 ошибок синхрона на перемотках, видео 60 fps. Минусы: другая кривая громкости (50 % ≈ −6 дБ против ≈ −29 дБ у DirectSound) — нужно подогнать; имена устройств у waveout обрезаны до 31 символа + « ($1,$64)» — сопоставлять сохранённое устройство по началу имени. Честный gapless возможен только после этого.
